# Source Integrations

This document describes all source integrations in Mori, their implementation status, capture methods, privacy boundaries, and trust models.

The source integration registry (`src/lib/sources/sourceRegistry.ts`)
catalogues every integration with its `IntegrationStatus`, `CaptureMode`,
`RawDataPolicy`, default trust level, and privacy note. Newer connector
work (`src/lib/connectors/captureSurfaces.ts`) catalogues capture **surfaces**
— the paste / hook / CLI / desktop / web / IDE paths a user actually clicks.
The two registries cover overlapping concerns and are bridged by the
[Modular Architecture](modular-architecture.md) doc. A future cleanup will
fold them into one registry; today they remain separate so the live UI
(Evidence Hub) doesn't have to migrate at the same time as the connector
matrix.

The Evidence Hub surfaces a curated subset of this registry to users; the
hub grouping logic is in
[`src/lib/sources/integrationGroups.ts`](../src/lib/sources/integrationGroups.ts).
"Available now" cards must be `implemented` or `partial` (and user-facing —
`tauriGitDiff`, `quickPass`, and `repository` are intentionally hidden so the
Hub never advertises internals as standalone import paths). "Planned
connectors" cards must be `planned` — Mori does not invent connectors that
have no registry entry.

## Overview

Mori reconstructs work sessions from **explicitly imported sources**. Every source has:

1. **Integration status**: Whether this source kind is implemented, partial, planned, mock-only, or unavailable
2. **Capture mode**: How Mori obtains this data (manual input, explicit import, desktop command, planned connector, or mock)
3. **Trust level**: Whether the source is verified (user-provided), observed (captured by Mori), or inferred (generated by analysis)
4. **Raw data policy**: What Mori retains (full data, summary only, redacted, or not captured)
5. **Privacy note**: Clear boundaries about when and how Mori accesses this data

## Integration Status Definitions

- **Implemented**: Fully functional, used in production sessions
- **Partial**: Core functionality works, but incomplete or experimental
- **Planned**: Not yet implemented, design documented
- **Mock-only**: Exists only in demo/mock data, not real
- **Unavailable**: Cannot be implemented due to technical/privacy constraints

## Trust Level Model

| Trust Level | Definition | Source Examples |
|-------------|------------|----------------|
| `verified` | User-provided or user-confirmed data | Manual notes, pasted URLs, pasted Git diffs, AI conversation imports |
| `observed` | Captured by Mori with user permission | Future: live Git diff capture, file watcher events, terminal history (when implemented) |
| `inferred` | Generated by analysis or AI | Quick Pass issues/decisions, AI summaries |

## Raw Data Policy

| Policy | Definition | Examples |
|--------|------------|----------|
| `retained` | Full original content stored | Manual notes, URLs, pasted Git diffs |
| `summaryOnly` | Only summary/metadata stored, original discarded | AI conversations (full transcript not stored) |
| `redacted` | Sensitive parts removed, rest stored | Future: terminal commands with secrets masked |
| `notCaptured` | Only references stored, no content | Repository paths (Mori never clones or indexes repo content) |

## Capture Modes

| Mode | Definition | User Control |
|------|------------|--------------|
| `manual` | User types/pastes data into Mori | Full control |
| `explicitImport` | User explicitly imports a file/URL/clipboard | Full control |
| `desktopCommand` | User runs command through Mori UI | Explicit per-action |
| `plannedConnector` | Future: opt-in connector after explicit user setup | Future: explicit opt-in |
| `mock` | Demo data only, not real capture | N/A |

## Implemented Integrations

### 1. Manual Note (`manualNote`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Retained (full text)
- **Privacy Note**: User explicitly types notes into Mori. No automatic capture.

**Usage**: User opens Import panel, selects "Manual Note", types/pastes text, and saves.

### 2. URL (`url`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Retained (URL + optional excerpt)
- **Privacy Note**: User explicitly pastes URL and optional excerpt. No browser history scanning.

**Usage**: User opens Import panel, selects "URL", pastes link and optional excerpt, and saves.

### 3. Claude Transcript (`claudeTranscript`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Summary only (full transcript not retained)
- **Privacy Note**: User explicitly pastes Claude conversation text. No API key access, OAuth, or automatic capture. Direct Claude API connector remains planned.

**Usage**: User opens Import panel, selects "AI 대화" tab, chooses "Claude" from platform dropdown, pastes conversation text, and saves. Mori parses turn structure (User/Assistant/System roles), detects code blocks and tool use, generates turn counts and token estimates, but does not store full transcript.

### 4. ChatGPT Transcript (`chatgptTranscript`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Summary only (full transcript not retained)
- **Privacy Note**: User explicitly pastes ChatGPT conversation text. No API key access, OAuth, or automatic capture. Direct ChatGPT API connector remains planned.

**Usage**: User opens Import panel, selects "AI 대화" tab, chooses "ChatGPT" from platform dropdown, pastes conversation text, and saves. Mori parses turn structure, detects code blocks and tool use, generates metadata, but does not store full transcript.

### 5. AI Conversation (Other) (`aiConversation`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Summary only (full transcript not retained)
- **Privacy Note**: User explicitly pastes conversation text from generic AI chat tools. No API key access or automatic capture.

**Usage**: User opens Import panel, selects "AI 대화" tab, chooses "Other AI Chat" from platform dropdown, pastes conversation text, and saves. Mori parses turn structure and generates metadata for AI chats that aren't Claude, ChatGPT, or Codex.

### 6. Git Diff (Pasted) (`gitDiff`)

- **Status**: Implemented
- **Capture Mode**: Manual input
- **Trust Level**: Verified
- **Raw Data Policy**: Retained (full unified diff)
- **Privacy Note**: User explicitly pastes output of `git diff` command. No repository scanning.

**Usage**: User runs `git diff` in terminal, copies output, opens Import panel, selects "Git Diff", pastes diff, and saves.

### 7. Git Diff (Tauri Desktop Command) (`tauriGitDiff`)

- **Status**: Implemented (desktop app only)
- **Capture Mode**: Desktop command
- **Trust Level**: Verified (user triggers command)
- **Raw Data Policy**: Retained (full unified diff)
- **Privacy Note**: User explicitly selects repository and range in Mori UI, then clicks capture. Mori runs sandboxed `git diff` command only when user clicks. No background scanning.

**Usage**: User opens Settings, adds repository path, returns to Import panel, selects "Git Diff", chooses repo/range from dropdown, and clicks Capture. Desktop app runs `git diff` command and imports result.

### 8. Repository (`repository`)

- **Status**: Implemented (metadata only)
- **Capture Mode**: Manual input
- **Trust Level**: N/A (metadata, not source content)
- **Raw Data Policy**: Not captured (only path reference)
- **Privacy Note**: User explicitly adds repository path in Settings. Mori NEVER clones, indexes, or scans repository content. Only used for reference in Git diff capture.

**Usage**: User opens Settings → Repositories, clicks "Add Repository", selects folder (desktop app) or types path (browser), optionally clicks "Verify" to check Git status. Repository path stored for Git diff dropdown convenience only.

### 8b. Connector JSONL (`connectorJsonl`)

- **Status**: Implemented (paste + desktop inbox)
- **Capture Mode**: Explicit import — paste or desktop inbox file pick
- **Trust Level**: Inherited from the underlying connector event (verified / observed / inferred per row)
- **Raw Data Policy**: Summary only by default; individual connector events declare their own policy
- **Privacy Note**: Mori reads JSONL **only** when the user pastes content or clicks **Refresh inbox** in the Connector JSONL tab. On Tauri desktop the Rust side restricts file access to `~/.mori/connectors/<family>/` (canonicalised, 8 MB cap, allowed extensions only). No background watching, no automatic polling, no symlink-escape, no live Claude/Codex/terminal sync.

**Usage**: User runs the Claude Code hook / Codex CLI wrapper / a terminal connector / a Git connector script, which appends to `~/.mori/connectors/<family>/*.jsonl`. In Evidence Hub the user opens **Connector JSONL** and either pastes the contents (browser fallback) or clicks **Refresh inbox** and picks a file (desktop). Parse / Preview runs automatically; the user reviews the preview card; clicking **Import to Review** sends the normalized events through Import Review before they reach the session. Every connector TimelineEvent carries a stable `connectorEventId` so subsequent imports detect duplicates and skip them by default — repeated inbox refreshes, successor files from the same connector session, **and even re-imports across saved sessions** (current + saved + in-file) all flow through the same identity index and do not duplicate Timeline cards. Identities round-trip through browser localStorage and through desktop SQLite (`events.connector_event_id`, added by migration V002), so cross-session detection survives an app restart.

### 9. Quick Pass Analysis (`quickPass`)

- **Status**: Implemented (deterministic heuristic + experimental Ollama)
- **Capture Mode**: Manual trigger
- **Trust Level**: Inferred (analysis output)
- **Raw Data Policy**: Summary only (issues/decisions/relationships extracted)
- **Privacy Note**: User explicitly clicks "Run Quick Pass" button. Analysis runs locally on imported sources. No data leaves the machine unless Ollama endpoint configured by user.

**Usage**: User imports sources, clicks "Run Quick Pass" in Review page banner. Mori analyzes imported sources to extract issues, decisions, relationships, and next actions.

## What Mori Will NEVER Do

To clarify privacy boundaries, here's what Mori explicitly **will not** do:

1. **Scan filesystem** without explicit user-added watch directories
2. **Index repository contents** — repositories are reference paths only
3. **Access browser history** without explicit extension install + opt-in
4. **Record terminal commands** without explicit shell integration opt-in
5. **Capture screenshots** without explicit user action
6. **Monitor clipboard** in background
7. **Access editor buffers** without explicit extension install + opt-in
8. **Send data to remote servers** unless user configures Ollama/LM Studio endpoint
9. **Store passwords, API keys, or secrets** in raw form (redaction rules apply to planned integrations)
10. **Auto-start sessions** — all sessions require explicit user Start action

## Evidence Traceability

Every source in Mori includes metadata for full evidence traceability:

```typescript
type SourceRef = {
  id: string;
  sessionId: string;
  kind: string; // Integration ID (manualNote, url, gitDiff, etc.)
  title: string;
  detail: string;
  trustLevel: "verified" | "observed" | "inferred";
  redactionStatus: "redacted" | "none";
  rawRetention: "full" | "summary" | "reference";
  capturedAt: string; // ISO timestamp
  relatedEventIds: string[];
  uri?: string; // Optional origin reference
};
```

**Traceability Chain**:
1. **Source** → created during import or analysis
2. **Event** → references source via `sourceRefs` array
3. **Issue** → references events via `sourceEventIds` array (indirect source link)
4. **Decision** → references events via `sourceEventIds` AND sources via `relatedSourceIds` (both indirect and direct)

**Evidence Helpers** (`src/lib/sources/traceability.ts`):
- `getSourceDisplayStatus()` — Get integration label, status, capture method, trust label, raw data policy
- `getEventEvidenceSources()` — Get sources for an event
- `getIssueEvidenceSources()` — Trace issue → events → sources
- `getDecisionEvidenceSources()` — Trace decision → events + direct sources
- `getBundleEvidenceSummary()` — Get integration/trust mix for bundles
- `getReportEvidenceSummary()` — Get full session evidence breakdown

## Implementation Checklist

When adding a new source integration:

1. [ ] Add entry to `sourceRegistry.ts` with full metadata
2. [ ] Implement import normalizer in `src/lib/import/`
3. [ ] Create `SourceRef` records with correct `kind`, `trustLevel`, `rawRetention`
4. [ ] Add input form to Import panel UI (`src/features/import/ImportPanel.tsx`)
5. [ ] Update Evidence page if new integration needs special display
6. [ ] Add tests for normalizer and traceability
7. [ ] Document integration in this file
8. [ ] Update privacy boundaries in `docs/product-spec.md`

## Connector capture path (NEW)

Beyond manual paste, Mori supports a structured **local connector**
capture path. External tools (Claude Code hooks, Codex CLI wrappers,
git scripts) write JSONL `ConnectorEvent` lines to a local file; Mori
imports the file when the user clicks Import.

The connector pipeline reuses existing `SourceKind` values rather than
introducing new registry entries:

| Connector id | Source kind reused |
|---|---|
| `claudeCodeHook` | `claudeTranscript` |
| `codexCliWrapper` | `codexTranscript` |
| `terminal` | `terminal` |
| `git` | `gitDiff` |
| `manual` | `manualNote` |

This keeps the connector path traceable through every existing
helper (`getSourceDisplayStatus`, `getReportEvidenceSummary`, etc.) and
avoids fake-promoting Planned registry entries to Implemented.

Implementation details:

- Pure pipeline: [`src/lib/connectors/`](../src/lib/connectors/)
- Event format: [`docs/connectors/connector-event-format.md`](./connectors/connector-event-format.md)
- Setup guides: [`docs/connectors/claude-code-hook.md`](./connectors/claude-code-hook.md)
  and [`docs/connectors/codex-cli-wrapper.md`](./connectors/codex-cli-wrapper.md)
- Templates: [`connectors/claude-code/`](../connectors/claude-code/),
  [`connectors/codex-cli/`](../connectors/codex-cli/)

What the connector path explicitly does not do:

- No live ingest daemon
- No automatic browser / app / file scanning
- No OAuth / API-key / credential capture
- No cloud sync
- No silent execution outside the explicit hook / wrapper invocation

### Capture surface matrix

Beyond the `SourceIntegration` registry, Mori tracks a **capture surface
matrix** — every user-visible path that moves evidence into the app,
with explicit status per surface (Implemented · Partial · Manual-only ·
Docs-template-only · Planned · Unavailable). The matrix covers paste
flows, local commands, hook templates, desktop / web imports, IDE
extensions, browser extensions, GitHub workflows, and the planned MCP
server.

- [`docs/connectors/capture-surface-matrix.md`](./connectors/capture-surface-matrix.md)
- [`docs/connectors/desktop-web-capture.md`](./connectors/desktop-web-capture.md)
- [`docs/connectors/github-pr-import.md`](./connectors/github-pr-import.md)

The matrix data is exported from
[`src/lib/connectors/captureSurfaces.ts`](../src/lib/connectors/captureSurfaces.ts).
UI surfaces (Settings, Evidence Hub) should read status copy from the
matrix rather than re-deriving it, so "no fake active connector buttons"
is enforced by data, not by code review.
