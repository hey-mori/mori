# Domain Model

> **Doctrine status (2026-07-14): legacy model, superseded as target.**
> This file describes the session-centric domain (Project / Session /
> Source / Event ...) that the code implements today. The **target**
> kernel is Record / SchemaDefinition / Context / Entity / Relation /
> Source / SourceLink / Derivation / Revision / Rule, defined in
> [`design/mori-context-workspace-architecture.md`](design/mori-context-workspace-architecture.md)
> §3. Sessions become `agent-session` records via adapters (§18 there);
> new capabilities build on the kernel, not on this shape. Keep this
> file for reading the existing code until the kernel lands.

The current TypeScript domain model lives in `src/domain/types.ts`. This document describes the product data model Mori should use as it grows from prototype into a local-first desktop app.

## Core Objects

### Project

A long-lived work container. A project groups sessions, sources, issues, decisions, artifacts, and summaries.

Typical fields:

- `id`
- `name`
- `description`
- `createdAt`
- `updatedAt`

### Session

A selected Start Mori to Stop Mori work unit.

Typical fields:

- `id`
- `projectId`
- `title`
- `startedAt`
- `endedAt`
- `recordingMode`
- `llmProvider`
- `llmModel`
- `storageLocation`
- `selectedSourceIds`
- `status`

### Event

A normalized unit on the Narrative Timeline. Events can come from AI conversations, file changes, browser research, terminal summaries, manual notes, decisions, issues, artifacts, or inferred analysis.

Typical fields:

- `id`
- `sessionId`
- `projectId`
- `start`
- `end`
- `type`
- `title`
- `summary`
- `sourceRefs`
- `linkedIssueIds`
- `linkedDecisionIds`
- `relationshipIds`
- `artifactIds`
- `trustLevel`
- `confidence`
- `createdBy`
- `userModified`

### Issue

A problem, uncertainty, risk, or follow-up item extracted from the session.

Typical fields:

- `id`
- `projectId`
- `sessionId`
- `title`
- `description`
- `status`
- `priority`
- `sourceEventIds`
- `relatedDecisionIds`
- `relatedFileIds`
- `suggestedNextAction`
- `assignee`
- `dueDate`
- `editedByUser`
- `editedAt`
- `confidence`
- `trustLevel`

### Decision

An important choice with rationale, alternatives, impact, and supporting evidence.

Typical fields:

- `id`
- `projectId`
- `sessionId`
- `title`
- `decision`
- `rationale`
- `rejectedOptions`
- `impact`
- `sourceEventIds`
- `relatedIssueIds`
- `relatedSourceIds`
- `editedByUser`
- `editedAt`
- `importance`
- `trustLevel`
- `confirmed`

`editedByUser` and `editedAt` are optional correction metadata on issues
and decisions. They mark that the current visible text was corrected by
the local user while keeping evidence, source event ids, trust, confidence,
status, and confirmation separate from the correction.

### Relationship

A typed link between events, issues, decisions, and artifacts. Relationships power Flow Focus and Trace View.

Typical fields:

- `id`
- `fromId`
- `fromType`
- `toId`
- `toType`
- `type`
- `confidence`
- `reason`

### Artifact

A generated or modified work output, such as a document, code file, report, prompt, design, email, or `.mori` package.

Typical fields:

- `id`
- `projectId`
- `sessionId`
- `title`
- `kind`
- `path`
- `sourceEventIds`
- `createdAt`

### Source

Evidence captured or imported into Mori.

Typical fields:

- `id`
- `sessionId`
- `kind`
- `title`
- `detail`
- `uri`
- `trustLevel`
- `redactionStatus`
- `rawRetention`
- `capturedAt`
- `relatedEventIds`

### Summary

Generated session summary, resume prompt, report content, and links to next actions.

Typical fields:

- `id`
- `sessionId`
- `sessionSummary`
- `resumePrompt`
- `reportMarkdown`
- `nextActionIds`
- `generatedAt`

### NextAction

A suggested continuation task.

Typical fields:

- `id`
- `sessionId`
- `title`
- `priority`
- `relatedIssueIds`
- `relatedEventIds`
- `done` · optional user-set completion state; absent means pending, so
  sessions saved before the completion capability stay valid
- `completedAt` · optional ISO timestamp, set when the user marks the
  action done and cleared when it is reopened

## Trust Levels

- `Verified`: the record is supported by explicit evidence such as a git diff, imported transcript, selected browser source, file change, or user note.
- `Observed`: the record is based on observed activity such as an active window, terminal summary, or source metadata.
- `Inferred`: the record was generated by AI analysis or relationship extraction and should be inspectable and correctable.

## Relationship Types

Use snake_case relationship names at package/storage boundaries:

- `led_to`
- `caused`
- `supported`
- `contradicted`
- `created_issue`
- `resolved_issue`
- `influenced_decision`
- `produced_artifact`
- `split_from`
- `merged_into`

The current TypeScript prototype uses camelCase equivalents:

- `ledTo`
- `caused`
- `supported`
- `contradicted`
- `createdIssue`
- `resolvedIssue`
- `influencedDecision`
- `producedArtifact`
- `splitFrom`
- `mergedInto`
